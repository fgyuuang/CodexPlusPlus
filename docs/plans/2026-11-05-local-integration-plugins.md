# 本地集成插件化：执行契约

用户授权：将本地功能迁入 v2.2.0 插件体系，优先处理 CLI 接入及 API 服务。仓库对应实现为 CLIProxyAPI、NewAPI；没有独立 FastAPI 集成代码。

## 审计与决策

- 范围：CLIProxyAPI/NewAPI 的管理页面、服务操作入口、插件启停和现有配置兼容。排除构建产物、上游合并历史、外部服务数据。
- 证据：两项 UI 和请求编排直接挂在 App.tsx，进入供应商页即探测两项服务；插件已有 manager.page/nav，但页面出口仅支持桌宠路由，不能直接调用既有原生服务。
- Structural decision：Refactor Backlog；本轮 Execution decision：Staged Refactor，按下列独立模块完成，不重写网关、服务或凭据管理。
- 契约：包拥有页面和用户操作编排；宿主提供限名、类型化的原生服务适配。服务操作必须经过已启用插件及当前清单的权限复核。不得开放任意 Tauri 命令、shell、内部设置或全量供应商凭据。
- 保持：原路径、DPAPI 密钥、受管供应商 ID、官方模型目录约束、CLI 独立路由、NewAPI Compose 和外部数据。插件停用撤下入口并阻止自启动，不自动停止独立服务或删除已有供应商。

## 分阶段范围与门禁

1. core 授权边界：新增仅供管理器的两条本地服务能力；基于 enabled + 有效清单 + manager.page + permissions.routes 逐次复核。预计 core 实现及测试各不超过 100 行。
2. 原生适配：复用现有 cliproxy/newapi 方法，显式操作白名单与反序列化；输出去掉密钥及 BackendSettings。新模块目标 200 行内；定向测试覆盖拒绝和输出投影。
3. 两个可启停插件包：复用同一无依赖面板，独立清单/导航/说明；服务字段、模型列表、启停、凭据保存、接入和控制台都由包绘制。共享页面目标 200 行、脚本目标 200 行，清单/说明另计；不把密钥移入明文插件配置。
4. 装配与迁移：随 bundled 发布；旧页面默认跳插件，保留显式旧版兼容入口；CLI 自启动复核插件状态。稳定供应商和密钥位置不变，避免数据搬迁。装配修改目标 120 行内，不删除尚未验收的旧实现。
5. 文档/验证：权限契约测试、包发现与停用测试、面板行为测试、TS/Rust 定向检查；最终一次后台完整发布。原始 v2.2.0 大规模脏合并保留，scope 全量扫描不能冒充小补丁预算通过。

## 不动与后续边界

官方登录、多账号额度耗尽调度、子代理来源、图片隔离及会话 provider 校验仍属核心安全边界。Fast、容量重试、额度继续、项目/Zed/worktree 已登记在内置拓展体系；本轮不重写其稳定实现。WorkBuddy/Claudian 模型接入继续使用上游 Agent 注册/网关，CLI 协作任务与模型供应商连接分别验收。

## 基线、回滚与停止

基线为已成功交付的 v2.2.0 源码和本机现有配置；先跑针对性基线，不启动重复全量测试。预期改动仅上列模块、插件文件、对应测试与文档，禁止依赖升级、原生程序下载、服务启停、登录/历史修改。

回滚：停用对应插件后使用原页面兼容入口；现有配置和独立服务数据原地保留。未验收前不删除旧服务实现和 Tauri 方法。若需要改变账号/路由归属、迁移密钥或越过上述模块预算，应重新审计和收敛，不以插件化名义进行整体重写。
