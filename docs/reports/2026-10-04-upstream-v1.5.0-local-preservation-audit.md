## 必须修复的合并回归与契约冲突

1. **P1，供应商切换重新写入 auth.json。** 上游将代理/API key 合并进实时 auth，
   与本地“认证源和请求目标分离”冲突。恢复本地 config-only 切换；只有显式、已验证的
   官方 auth override 可以写认证。回归断言覆盖新旧令牌、损坏快照、空文件和往返切换，
   同时检查 provider bearer 可用，不通过删测试消除冲突。
2. **P1，流式失败没有合法 Responses 终止事件。** 早期连接失败、非 2xx 和错误正文
   读取失败统一返回 HTTP 200 `response.failed` SSE；传输中断、空闲超时、缺少终止事件和
   上游 failed/incomplete 都记录 `helper.protocol_proxy_stream_failed`。
3. **P1，压缩流丢失预读数据并把失败记成功。** 将 prefetched chunk 交回转换器，
   增加超时与上游终止验证，根据最终 SSE 判断失败；保留上游压缩项格式。
4. **P1，CLIProxyAPI 官方别名能力继承断开。** 统一解析器增加受信别名路径，
   从官方目录复制基础能力；普通供应商同名模型不能借用官方能力。
5. **P2，混合目录追加官方条目恢复不支持的 Lite。** 指向本地 HTTP 代理的官方条目
   统一关闭 Lite 与 WebSocket，显式用户元数据覆盖仍由后续覆盖步骤处理。
6. **P2，Windows 根路径识别。** 单独 `/` 或 `\` 也是当前盘根；不能因缺盘符放行。
7. **P2，微信白名单过滤无状态提示。** 保留本地配对审批，同时恢复上游过滤提示。
8. **P2，测试仍引用旧弹窗结构或沿用前一场景的空模型目录。** 测试使用新账号入口，
   Fast 请求测试重新提供官方能力目录，不增加生产代码的名称猜测。
