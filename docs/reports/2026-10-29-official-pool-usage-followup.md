# 官方用量、供应商池账号迁移与上游同步

基线为已交付并提交的 v2.0.0 本地整合 `97b4ff42`。本轮目标是解释官方登录用量偏低、补齐统计、保留登录接入供应商池，并审查相关上游更新。

## 审计证据

`gateway::usage::record_entry_in` 从请求日志的上游 usage 汇总，按本地日期、Agent、供应商和模型保存到 gateway-usage.json。缓存输入已包含在 inputTokens、推理已包含在 outputTokens，不能再加一次。订阅剩余额度是另一套 wham/usage 窗口指标，不能换算为历史 Token 总数。

统计不限新版网关，但必须经过已接入记录器的 Codex++ 请求链。原本受保护的本地官方 HTTP/SSE 处理器提前分流，没有创建 ProxyRequestLog，因此当前官方账号和顺序调度流量漏计。修复补接该记录器，终止 SSE 解析提取 usage，包含输入、输出、缓存和推理；不改变出站身份，不记录提示词、图片或凭据。

本次只读快照的真实统计文件今天累计 330 tokens，另有 1970-01-01 以及少量固定数字、模型组合，符合测试样本特征。找到请求日志测试覆盖路径、用量却仍写默认用户目录的隔离缺口。已修复新写入路径；不能据此确定所有旧行均可删除，因此原数据与备份保留。用户看到的 600 多并不代表全部官方聊天只消耗这些 tokens，也不能承诺此次修复会回填历史。

## 保留登录的迁移方式

当前本地官方体验及双账号顺序调度均开启。官方账号元数据、加密凭据、账号目录、settings 和原用量已通过 Copy-Item 备份至用户状态目录 backups/official-pool-migration-20261029-165957，未将凭据复制进仓库或供应商池。

上游供应商池支持独立 ChatGPT 订阅登录。直接复制现有 refresh token 会形成两个刷新者，因此新增账号库引用：池里只保存账号 ID 和该账号已缓存模型，使用时由原 OfficialAccountStore 校验身份、启用状态和令牌刷新。删除、停用、损坏的引用失败，不回退到 live 登录或其他账号。原本账号、直连配置、历史和插件保持。

「添加供应商 → 导入…」新增单账号接入及「保留登录并迁移顺序调度」。后一入口按原设置的账号顺序创建账号引用和每个模型的专用官方顺序组，不改变 Agent 绑定、当前聊天、默认模型或 config/auth。重复迁移保留用户编辑过的组；不会自动把普通聚合转换成官方调度。

正式接入网关后，明确选择对应「官方顺序调度」组：仅同模型的本地官方引用可参与，组模式只能依次且不允许粘性重新排序、权重或第三方。只有明确额度耗尽可尝试下一账号；认证失败、普通限流、模型不支持、连接故障停止。普通裸官方模型继续要求唯一来源，子代理固定根请求已确认的账号，不跟随父请求的候选重新调度。重启后的来源绑定仍需根请求重建。

迁移入口需新版 Manager 生效后执行；本轮没有趁用户正在对话切换当前路由，也尚未将新代码视为真实网关接入验收成功。另提供 `--codex-plus-migrate-official-pool` 无窗口命令；仅在网关尚未启用时准备池与组，已有 gateway.json 先做同目录备份。

本轮后台发布后续任务使用 `scripts/migrate-official-pool-after-release.ps1 -Job <编号>`：只在该次发布 succeeded 且 bin Manager 哈希一致后运行迁移命令，单独保存 official-pool-migration.json；发布失败、超时、活跃网关或命令失败均不自动重试。执行前后只对登录、配置及账号库文件计算哈希，不输出内容，不更改这些文件。发布成功与迁移成功是两个独立状态，迁移完成仍不代表已启用网关或真实对话验收通过。
