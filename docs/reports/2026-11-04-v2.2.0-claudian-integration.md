## 分支错误根因与修复边界

错误：`This chat uses codex_plus_official_schedule, but your current provider is openai`。

已核对本机 Codex 26.1029.7803.0 及官方源码 `7ce5fa7`：`ConfigManager::load_for_resume` 在请求参数覆盖前校验保存的 provider。仅附加 modelProvider 或补 provider 表不再足够。

- 普通 `thread/fork`：只读确认父来源与模型，按当前 catalog 的精确迁移表使用同一账号/官方专用顺序组，创建时采用当前网关传输；不修改父历史，不触碰预测分支。
- 原会话恢复：前端及 helper 分别通过原生接口确认卸载；复用备份、锁、CAS 与恢复日志，只迁移单个 thread ID 的 session_meta 和 SQLite provider。配置/auth、历史消息及其他会话不变。
- 来源不唯一、账号不在池内、第三方混入官方顺序组、活动/仍加载实例或备份失败时拒绝；不使用 catalog 默认模型替代来源，不为修复而重放用户输入。
- 旧原生进程必须由用户安排重启加载新闭包；仍加载的旧聊天可能需要先保存工作并重启。历史加密内容与账号绑定的限制继续存在。
