## 分阶段本地更新

| 顺序 | 适配范围 | 本地边界与验收 |
|---|---|---|
| 1：请求日志 | 上游 request_log、请求状态条、commands/routes 和 Manager 日志页；与本地 protocol_proxy 对接 | 先做观测再做重试。只记录白名单元数据；关联父/子 thread、实际 sourceId、尝试次数、根因、首字时间、token/缓存统计，敏感错误必须脱敏。验证同一父聊天切换前后旧子代理的实际出站账号，禁止记录凭据、正文、图片或工具参数。进行中/完成/失败必须完整收口。 |
| 2：请求避震 | ProxyAutoRetry、StreamStartCommitPolicy 与协议转发 | 本地官方直连、第三方直连、聚合、CLIProxy 各走现有路由。传输重试留在当前账号，明确额度耗尽才交给顺序调度；普通 429、容量或断流不能静默换账号。提交文本/工具事件后不得重放；取消必须停止退避，预算有界，失败返回合法 response.failed。官方图片不进入第三方轮转。缓冲模式先 opt-in，不照搬上游默认开启。 |
| 3：供应商兼容 | RelayProfile 的 trust_upstream_catalog_lite、strict_responses_reasoning、逐模型 codex_plus_reasoning_parameters 与转换器 | 新字段采用兼容默认值和旧配置往返验证；严格推理历史只限明确启用的 Responses 供应商。保持官方动态目录精确匹配、裸名关闭式路由、别名映射、reasoning 能力校验及现有 Luna Ultra 尝试。先分别验证 Responses/Chat/Anthropic/Gemini 的历史、工具、图片和流终止，再接 UI。 |
| 4：会话/项目 | 新列表、分页缓存、搜索、批量选择，随后独立评估 sync_journal/归档写流程 | 先吸纳只读交互，保留 openai/custom 的唯一会话、rollout、SQLite 统计和现有 provider 归一规则；批量范围跨页/跨项目需明确，归档/数据库改写单独备份、回滚和故障恢复测试。不能用新版 storage 整体替换本地实现。 |

| 6：平台/官网 | Windows 共享稳定性修复优先，macOS/WSL 按实际路径适配；官网预览/图标/赞助独立 | 不为官网预览更换本地依赖/品牌；不套用 macOS 产物与上游默认提交 main 的维护指令。平台代码须可编译、路径正确，不改变本机既有部署与自启动选择。 |

## 接收与发布门槛

每阶段只处理一个边界，先补生产路径可复现的 mock/回归，再接设置和界面；完整回归与编译仅启动一次后台发布，不在聊天轮询。默认保留现有行为，新增能力显式开启；源文件或 dist 在构建中变化必须阻止交付。
真实验收至少包含：账号2先用、明确限额后账号1；原聊天手动双向切换；切换前创建的子代理继续使用；普通第三方/聚合不越界；官方图片、compact 与失败 SSE。日志只证明出站身份，真实账号额度变化仍需实际使用核对。
各阶段完成后再处理既有合并收尾；提交/推送前必须有成功后台任务和用户启动新版验收。当前不改写历史、自动提交、推送或虚报 v1.10.1 全量更新。
